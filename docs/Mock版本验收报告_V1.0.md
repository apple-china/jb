# 加贝云·化妆预约 Mock 版本验收报告 V1.0

> 2026-09-06：本报告仅证明旧版 Mock 的测试结果，不证明 [最新 V1.0 需求基线](加贝云_V1.0_确认需求基线.md) 已实现。新增角色、预约规则、门禁签到及迟到通知须另行开发和验收。

验收日期：2026-09-05（Asia/Shanghai）

## 结论

本地 Mock V1.0 达到“可运行、可重置、可验证”的交付标准，并已完成首轮 23 条与第二轮 22 条界面验收整改。主播预约闭环、管理员运营闭环、PostgreSQL 硬约束、会话与权限、每日群卡片投影、第三方故障模拟、启动脚本和开发文档均已实现。所有真实第三方能力保持为 Mock，没有调用生产接口或发送真实通知。

真实钉钉企业、目标群、目标钉钉终端、Docker/Testcontainers runner、生产备份恢复与监控平台不具备本次本机验证条件，明确列为未验证，不计作通过。

## 第二轮界面整改验证

- 22 条浏览器批注已逐项落地，覆盖按钮与时间排版、取消态、公开日程团队、可读预约号、自定义下拉与时间滚轮、代预约空初始态，以及老师/团队/管理员维护控件。

- 资源名称同时具备前端禁用提交与服务端 422 校验；编辑界面不要求操作原因，但审计原因仍自动随请求写入。
- Playwright 在 360px 与桌面双项目共 8/8 通过，API 冒烟增加到 24/24。

## 代表性异常场景

- 缺少 CSRF、非白名单 Origin、主播访问管理接口、无权限员工读取预约数据均返回 403。
- 客户端伪造 `streamerUserId`、`role`、`displayName` 不改变服务端当前身份。
- 同一幂等键返回同一预约；并发争抢仅一个成功。
- `CANCELLED` 仍占主播日期资格，`VOIDED` 释放；老师只被 `ACTIVE` 时间区间占用。
- 卡片支持 Token 过期、网络超时、HTTP 5xx、结果未知、原卡删除和乱序版本故障注入。
- 卡片失败不回滚预约，旧内容版本不能覆盖新版本。
- 有未来有效预约的老师/团队首次停用只返回影响数量，确认后重计数再生效。
- 两名管理员并发互相停用时，仅一方成功，始终保留至少一名启用管理员。

## 未验证与限制

- 未提供钉钉测试企业凭据、目标群和卡片模板，真实 JSAPI、Token、用户身份与卡片创建/更新未联调。
- 未在钉钉 Android、iOS、PC 容器内真机验证。
- 当前主机无 Docker，Compose 启动和 Testcontainers runner 未执行；同一数据库规则已在真实 PostgreSQL 16.15 上验证。
- 当前主机无 LibreOffice，原始 DOCX 已做文本/结构检查但未做页面渲染。
- 生产备份恢复演练、告警阈值与接收人需在部署环境确认。
