# 加贝云·化妆预约——第三方接口契约

> 2026-09-06：接口契约保留供后续真实联调核验；业务范围和匹配规则以 [V1.0 确认需求基线](加贝云_V1.0_确认需求基线.md) 为准。原 V1.1 门禁及迟到提醒已纳入 V1.0；不可沿用与新窗口、重复预约证据复用、通知条件冲突的旧业务表述。

## 0. 2026-09-06 业务调用约束更新

- DT-04/DT-05 的外部字段、鉴权和错误处理契约保持参考价值；取消09:00固定首发。安排卡片由预约日期首条有效预约自动触发，或由超管/运营手动触发。
- 同一群＋预约日期复用一个当前卡片业务键。首次投放失败须重试且不能标记为已成功；已投放后的预约变化使用DT-05更新原卡，原卡不可恢复时才使用DT-04创建替代卡。
- MD-01～MD-03全部进入V1.0真实联调范围。门禁业务有效窗口改为预约前120分钟之后至预约日期当天结束，取首次打卡；不得沿用旧6小时至预约结束窗口。
- 同一原始门禁事件须去重保存，但允许不同的新有效预约在各自窗口内重新查询同一证据；不得再以“一事件只能关联一预约”作为业务限制。
- 迟到提醒仍使用独立卡片：只提醒开始后10分钟仍无有效打卡者，每预约最多一次；已迟到打卡者不催。无钉钉绑定者不能生成虚假的 @ 成功结果。
- 以上调整改变业务触发和匹配，不擅自改变真实第三方字段、签名算法或平台错误码；仍须用真实脱敏回调和测试群验证。

### 2.3 接口数量

- V1.0：5个接口。
- V1.1：新增3个接口契约。
- 合计：8个接口契约。

## 3. 环境与配置

### 3.1 Base URL

| 平台 | Base URL |
|---|---|
| 钉钉新版服务端 API | `https://api.dingtalk.com` |
| 钉钉旧版 TOP API | `https://oapi.dingtalk.com` |
| 魔点钉钉渠道 | `https://toapi.moredian.com` |
| 本项目后端示例 | `https://<APP_API_DOMAIN>` |

不得将魔点非钉渠道 `https://oapi.moredian.com` 用于本项目。

### 3.2 后端环境变量

| 变量名 | 用途 | 是否敏感 |
|---|---|---:|
| `DINGTALK_CLIENT_ID` | 钉钉 Client ID；企业内部应用对应原 AppKey，服务商套件才对应原 SuiteKey，本项目不使用 SuiteKey | 否（受控标识） |
| `DINGTALK_CLIENT_SECRET` | 钉钉 Client Secret；企业内部应用对应原 AppSecret，服务商套件才对应原 SuiteSecret，本项目不使用 SuiteSecret | 高度敏感 |
| `DINGTALK_CORP_ID` | 钉钉企业 CorpId | 否（受控标识） |
| `DINGTALK_ROBOT_CODE` | 企业机器人编码；内部机器人通常使用 AppKey | 是 |
| `DINGTALK_GROUP_OPEN_CONVERSATION_ID` | 目标群 openConversationId | 是 |
| `DINGTALK_SCHEDULE_CARD_TEMPLATE_ID` | 今日安排卡片模板ID | 否 |
| `DINGTALK_LATE_CARD_TEMPLATE_ID` | 迟到提醒卡片模板ID | 否 |
| `DINGTALK_APP_ENTRY_URL` | “进入预约”按钮地址 | 否 |
| `MOREDIAN_ORG_ID` | 魔点 OrgID；接口字段名为 `orgId` | 否（受控标识） |
| `MOREDIAN_ORG_AUTH_KEY` | 魔点机构授权Key | 高度敏感 |
| `MOREDIAN_DEVICE_SN` | 公司唯一门禁设备SN | 是 |
| `MOREDIAN_CALLBACK_URL` | 生产识别回调地址 | 否 |

禁止把任何 Secret、OrgAuthKey、AccessToken 下发给前端。

联调配置只允许通过环境变量、部署平台 Secret 或密码管理工具注入。仓库仅提交 `.env.example`，其中保留变量名和空值；本地真实值放入被 Git 忽略的 `.env.integration.local`，不得写入本文、开发提示词、README、截图或测试报告。`DINGTALK_CLIENT_ID`、`DINGTALK_CORP_ID` 和 `MOREDIAN_ORG_ID` 虽不是鉴权秘密，也按受控配置管理；`DINGTALK_CLIENT_SECRET` 和 `MOREDIAN_ORG_AUTH_KEY` 必须按密钥管理并定期轮换。

### 3.3 上线前人工配置

1. 钉钉企业内部应用已经创建并发布；
2. 配置微应用首页地址、PC端首页地址及安全域名；
3. 开通接口所需权限，至少包含互动卡片实例写权限；
4. 创建并发布“今日安排”“迟到提醒”两套卡片模板；
5. 企业机器人已经安装到目标群；
6. 取得并保存目标群 `openConversationId`；
7. 魔点应用选择“钉钉渠道”；
8. 取得魔点 `orgId`、`orgAuthKey`；
9. 魔点开放平台中已添加注册回调接口权限；
10. 生产回调使用公网可访问的 HTTPS 443 地址。

魔点应用编辑页中的“应用级回调 URL”用于平台定义的组织授权或生命周期类通知，不等同于本文 MD-03 的 `REC_SUCCESS` 识别成功事件，也不能替代 MD-01 获取企业 AccessToken 和 MD-02 注册机构回调。单组织自用且不需要该类生命周期通知时，可不配置应用级回调 URL；V1.1 的门禁识别链路仍以 MD-02 注册的业务回调地址为准。

目标群固定配置，因此 V1.0 不增加 `dd.chooseChat`。如果以后允许管理员更换群，再单独增加该 JSAPI。

## 4. DT-01 获取微应用免登授权码

### 4.1 官方文档

- [企业内部应用免登流程](https://open.dingtalk.com/document/development/enterprise-internal-application-logon-free)
- [requestAuthCode JSAPI](https://open.dingtalk.com/tools/explorer/jsapi?id=11723)

### 4.2 基本信息

| 项目 | 内容 |
|---|---|
| 调用位置 | 钉钉 H5 微应用前端 |
| 调用方式 | `dd.requestAuthCode` |
| 前置条件 | 页面运行于受支持的钉钉客户端内 |
| 最低版本 | 移动端 7.0.45；PC端 7.0.50（以最新官方文档为准） |

核验结论：截至 2026-09-04，钉钉官方 JSAPI Explorer 明确展示 `dd.requestAuthCode`，并要求 `clientId` 与 `corpId`。本项目继续使用该名称；`dd.runtime.permission.requestAuthCode` 不作为本契约实现依据。上线前仍须在目标移动端和 PC 端真机验收。

### 4.3 请求参数

| 字段 | 类型 | 必填 | 来源 | 说明 |
|---|---|---:|---|---|
| `clientId` | String | 是 | 前端非密钥配置 | 企业内部应用 Client ID，原 AppKey |
| `corpId` | String | 是 | URL注入或非密钥配置 | 当前企业 CorpId |

`corpId` 可通过微应用首页地址中的 `corpid=$CORPID$` 由钉钉解析后取得。前端必须校验取得的 CorpId 与允许的企业一致。

### 4.4 成功响应

```json
{
  "code": "hYLK98jkf0m"
}
```

`code` 是一次性免登码，应立即发送给本项目后端；不得写入持久化日志。

### 4.5 前端调用示意

```javascript
function requestDingTalkAuthCode(clientId, corpId) {
  return new Promise((resolve, reject) => {
    dd.requestAuthCode({
      clientId,
      corpId,
      success: ({ code }) => resolve(code),
      fail: reject
    });
  });
}

const code = await requestDingTalkAuthCode(
  DINGTALK_CLIENT_ID,
  DINGTALK_CORP_ID
);
```

前端随后调用本项目内部登录接口，例如：

```http
POST /api/auth/dingtalk/login
Content-Type: application/json

{
  "authCode": "<ONE_TIME_AUTH_CODE>"
}
```

### 4.6 异常处理

- 不在钉钉容器中：生产环境提示“请在钉钉内打开”；本地开发使用显式 Mock 身份模式。
- 用户取消或客户端返回错误：允许用户重新触发免登。
- 不在受支持版本：提示升级钉钉。
- 禁止无限循环自动重试。

### 4.7 Mock约定

本地前端可注入：

```json
{
  "code": "mock-auth-code-streamer-001"
}
```

Mock身份切换仅在 `development`、`test` 环境开放，生产构建必须禁用。

## 5. DT-02 获取钉钉企业内部应用AccessToken

### 5.1 官方文档

[获取企业内部应用AccessToken](https://open.dingtalk.com/document/development/obtain-the-access-token-of-an-internal-app)

### 5.2 请求

```http
POST https://api.dingtalk.com/v1.0/oauth2/accessToken
Content-Type: application/json
```

```json
{
  "appKey": "${DINGTALK_CLIENT_ID}",
  "appSecret": "${DINGTALK_CLIENT_SECRET}"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `appKey` | String | 是 | 企业内部应用 Client ID/AppKey |
| `appSecret` | String | 是 | 企业内部应用 Client Secret/AppSecret |

### 5.3 成功响应

```json
{
  "accessToken": "<REDACTED>",
  "expireIn": 7200
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `accessToken` | String | 钉钉服务端API访问凭证 |
| `expireIn` | Long | 有效期，单位秒；官方当前值为7200 |

### 5.4 成功判定

- HTTP 2xx；
- `accessToken` 非空；
- `expireIn > 0`。

### 5.5 缓存规则

1. 后端全局复用，不允许每次业务调用都重新获取；
2. 缓存键应包含应用 Client ID；
3. 建议在到期前300秒刷新；
4. 并发刷新必须使用单飞/互斥控制，防止同时刷新；
5. Token只保存在服务端内存或安全密钥存储中，日志必须脱敏。

### 5.6 错误与重试

| 情况 | 处理 |
|---|---|
| `400 invalidClientIdOrSecret` | 不重试；报警并检查配置 |
| 网络超时、HTTP 5xx | 指数退避重试，最多3次 |
| 下游API提示Token失效 | 清除缓存，仅强制刷新1次后重放原请求 |

## 6. DT-03 通过免登码获取用户信息

### 6.1 官方文档

[通过免登码获取用户信息](https://open.dingtalk.com/document/development/obtain-the-userid-of-a-user-by-using-the-log-free)

### 6.2 请求

```http
POST https://oapi.dingtalk.com/topapi/v2/user/getuserinfo?access_token=<DINGTALK_ACCESS_TOKEN>
Content-Type: application/json
```

```json
{
  "code": "<ONE_TIME_AUTH_CODE>"
}
```

| 位置 | 字段 | 类型 | 必填 | 说明 |
|---|---|---|---:|---|
| Query | `access_token` | String | 是 | DT-02取得的Token |
| Body | `code` | String | 是 | DT-01取得的免登码 |

免登码有效期为5分钟，并且只能使用一次。

### 6.3 成功响应（项目使用字段）

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "result": {
    "userid": "streamer001",
    "device_id": "device-example",
    "sys": false,
    "sys_level": 0,
    "associated_unionid": "associated-union-example",
    "unionid": "union-example",
    "name": "示例主播"
  },
  "request_id": "request-example"
}
```

### 6.4 成功判定及字段映射

成功条件：

```text
HTTP 2xx AND errcode == 0 AND result.userid 非空
```

| 钉钉字段 | 本地字段 | 用途 |
|---|---|---|
| `result.userid` | `users.dingtalk_user_id` | 企业内用户唯一标识，主业务键 |
| `result.name` | `users.display_name` | 展示名称快照 |
| `result.unionid` | 可选保存 | 暂不作为本项目主业务键 |
| `result.sys/sys_level` | 不作为权限依据 | 项目管理员权限由本地数据库配置 |
| `request_id` | 结构化诊断日志 | 排查第三方请求，禁止关联敏感正文 |

后端根据本地数据库判断：

- 有效管理员 → 管理端；
- 有效主播 → 主播端；
- 其他用户 → 无权限。

不得根据前端传入角色或仅根据 `sys/sys_level` 授权本项目管理员权限。

### 6.5 重试规则

免登码只能使用一次。发生以下情况时不要无限重放同一个Code：

- 已收到钉钉明确业务失败：前端重新获取Code；
- 网络结果不确定：最多进行一次受控处理，仍失败则重新获取Code；
- 后端必须避免把同一个Code持久化为长期凭证。

### 6.6 Mock

## 7. DT-04 创建并投放互动卡片

### 7.1 官方文档

- [创建并投放卡片](https://open.dingtalk.com/document/development/create-and-deliver-cards)
- [钉钉互动卡片官方示例](https://github.com/open-dingtalk/dingtalk-card-examples)

### 7.2 请求

```http
POST https://api.dingtalk.com/v1.0/card/instances/createAndDeliver
x-acs-dingtalk-access-token: <DINGTALK_ACCESS_TOKEN>
Content-Type: application/json
```

权限：互动卡片实例写权限。

### 7.3 项目使用的请求字段

| 字段 | 类型 | 必填 | 项目约定 |
|---|---|---:|---|
| `cardTemplateId` | String | 是 | 已发布的卡片模板ID |
| `outTrackId` | String | 是 | 本项目生成的卡片实例业务唯一ID |
| `cardData.cardParamMap` | Map<String,String> | 是 | 群成员共用的公共数据 |
| `privateData` | Map<String,Object> | 否 | 按钉钉userId隔离的私有数据 |
| `openSpaceId` | String | 是 | 群场域：`dtv1.card//IM_GROUP.<openConversationId>` |
| `imGroupOpenSpaceModel.supportForward` | Boolean | 是* | 项目固定为 `false`，避免预约安排被转发 |
| `imGroupOpenSpaceModel.notification.alertContent` | String | 否 | 系统通知栏摘要文案 |
| `imGroupOpenSpaceModel.notification.notificationOff` | Boolean | 否 | 每日卡片可关闭强提醒；迟到卡片设为 `false` |
| `imGroupOpenDeliverModel.robotCode` | String | 是* | 企业内部机器人使用机器人AppKey/编码 |
| `imGroupOpenDeliverModel.atUserIds` | Map<String,String> | 否 | 群消息层@人，key=userId，value=姓名 |
| `imGroupOpenDeliverModel.recipients` | Array<String> | 否 | 本项目公共日卡不限制接收者 |
| `cardAtUserIds` | Array<String> | 否 | 卡片正文@人名单 |
| `userIdType` | Integer | 否 | 固定 `1`，表示userId |

“是*”表示使用对应群聊模型时必填。

`privateData` 限制：

- key为用户userId，最长不超过100B；
- 每个用户的value最长不超过1KB。

```json
  "openSpaceId": "dtv1.card//IM_GROUP.<OPEN_CONVERSATION_ID>",
  "imGroupOpenSpaceModel": {
    "supportForward": false,
    "notification": {
      "alertContent": "加贝云·今日化妆安排",

```

没有预约的已知主播，其私有区显示“今天暂未预约”。`privateData` 仅为本地启用主播生成；纯管理员不生成无意义私有区，同时具备管理员和主播身份的用户按主播规则生成。该范围不依赖取得群内全员名单。

### 7.5 迟到@提醒卡片请求示例

迟到提醒必须创建一张新卡片，不能只更新每日安排卡片。为兼顾消息通知层和卡片正文展示，项目同时设置：

- `imGroupOpenDeliverModel.atUserIds`；
- `cardAtUserIds`；
- Markdown变量中的 `<a atId=...>姓名</a>`。

```json
{
  "cardTemplateId": "${DINGTALK_LATE_CARD_TEMPLATE_ID}",
  "outTrackId": "late-reminder-appointment-12345",
  "cardData": {
    "cardParamMap": {
      "title": "化妆签到提醒",
```

### 7.6 成功响应

```json
{
  "success": true,
  "result": {}
}
```

成功条件：HTTP 2xx 且 `success == true`。保存 `outTrackId`、群、业务日期、模板ID、创建状态和更新时间。

### 7.7 幂等与重试

1. 每个 `outTrackId` 唯一标识一张卡片；
2. 今日安排卡片应对“群+业务日期”建立数据库唯一约束；
3. 迟到提醒应对“预约ID+提醒类型”建立唯一约束；
4. 请求结果不确定时，必须复用原 `outTrackId`，禁止生成新ID盲目重发；
5. 收到 `param.cardAlreadyExist` 时，转为更新流程或标记已创建；
6. `system.busy`、HTTP 5xx和网络超时可指数退避重试；
7. 参数、模板、权限错误不得无限重试；
8. 卡片发送失败不得回滚已经成功提交的预约，数据库是事实源。

### 7.8 主要错误

| 错误 | 处理 |
|---|---|
| `param.cardAlreadyExist` | 使用原卡片记录并转更新，禁止新建重复消息 |
| `param.templateNotExist` | 停止重试，检查模板ID |
| `param.templateUnpublished` | 停止重试，发布卡片模板 |
| `param.openSpaceIdInvalid` | 检查群openConversationId及格式 |
| `param.userIdNotExist` | 检查钉钉userId及企业归属 |
| `param.contentUnsafe` | 停止重试并记录安全审查错误 |
| `system.busy` | 指数退避重试 |

## 10. MD-02 注册魔点识别回调

### 10.1 官方文档

[注册回调](https://open.moredian.com/#/doc/interface/1/10006/32)

### 10.2 请求

```http
POST https://toapi.moredian.com/callback/addOrgCallback?accessToken=<MOREDIAN_ACCESS_TOKEN>
Content-Type: application/json
```

```json
{
  "callbackUrl": "https://<APP_API_DOMAIN>/api/v1/integrations/moredian/recognition-events",
  "callbackTag": "REC_SUCCESS"
}
```

| 位置 | 字段 | 类型 | 必填 | 约束 |
|---|---|---|---:|---|
| Query | `accessToken` | String | 是 | MD-01取得 |
| Body | `callbackUrl` | String | 是 | 长度小于128；端口只能为80或443；生产使用HTTPS 443 |
| Body | `callbackTag` | String | 是 | 本项目固定 `REC_SUCCESS` |

### 10.3 重要语义

该接口是全量覆盖接口，以最后一次调用提交的回调配置为准。

如果未来增加其他Tag，必须发送完整集合，例如：

```json
{
  "callbackUrl": "https://<APP_API_DOMAIN>/api/integrations/moredian/events",
  "callbackTag": "REC_SUCCESS,OTHER_TAG"
}
```

不得只发送新增Tag导致原订阅被覆盖。

### 10.4 成功响应

```json
{
  "result": "0",
  "message": "操作成功"
}
```

成功条件：HTTP 2xx 且 `String(result) == "0"`。

### 10.5 调用策略

- 可由受控部署脚本或管理员运维命令调用；
- 不应在每次应用启动时无条件重复注册；
- 域名、路径、Tag或机构授权发生变化时重新注册；
- 生产首次注册后必须进行一次真实刷脸验证；
- 记录注册时间、回调URL摘要、Tag和结果，但不记录Token。

## 11. MD-03 接收魔点识别开门记录

### 11.1 官方文档

[识别开门记录回调说明](https://open.moredian.com/#/doc/interface/1/10006/34)

### 11.2 本项目接收地址

```http
POST https://<APP_API_DOMAIN>/api/v1/integrations/moredian/recognition-events
Content-Type: application/json
```

调用方向：魔点 → 加贝云后端。

### 11.3 Query参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `orgId` | String | 是 | 机构ID |
| `signVersion` | String | 是 | 签名版本，文档示例为 `1` |
| `timestamp` | String/Long文本 | 是 | 毫秒时间戳 |
| `nonce` | String | 是 | 随机字符串 |
| `signature` | String | 是 | 魔点签名值 |

### 11.4 Body

```json
{
  "callbackTag": "REC_SUCCESS",
  "data": {
    "memberId": "streamer001",
    "deviceSn": "0101010101NC0101",
    "recognizeTime": "1788495600000",
    "fileKey": "optional-capture-file-key"
  }
}
```

| 字段 | 类型 | 必填 | 业务映射 |
|---|---|---:|---|
| `callbackTag` | String | 是 | 必须等于 `REC_SUCCESS` |
| `data.memberId` | String | 是 | 钉钉渠道中对应钉钉 `userId` |
| `data.deviceSn` | String | 是 | 必须匹配配置的公司门禁SN |
| `data.recognizeTime` | String | 是 | Unix毫秒时间戳，转换为Asia/Shanghai |
| `data.fileKey` | String | 否 | 仅开启文件回调时出现；V1.1不下载图片 |

`memberId` 必须以字符串保存和比较，不得转为JavaScript Number或数据库整数。

### 11.5 验签

必须先读取原始请求Body字节/字符串，再进行JSON反序列化。

```text
bodyMd5  = MD5(rawBody)，32位小写
signText = nonce + orgId + signVersion + timestamp + bodyMd5
expected = BASE64(HMACSHA1(signText, orgAuthKey))
```

使用常量时间比较 `expected` 与Query中的 `signature`。

禁止对JSON反序列化后重新序列化再计算MD5，因为字段顺序或空白变化会导致验签失败。

魔点失败重试最长可持续24小时，因此在未确认重试是否更新 `timestamp` 前，不设置会误拒绝合法重试的极短时间窗口；防重放主要依赖签名、机构校验、设备校验和事件幂等键。

### 11.6 回调去重

官方回调没有提供独立事件ID。本项目生成：

```text
dedup_key = SHA-256(orgId + "|" + memberId + "|" + deviceSn + "|" + recognizeTime)
```

数据库对 `dedup_key` 建立唯一约束。重复回调返回成功，不重复生成签到记录、不重复更新预约、不重复发送提醒。

### 11.7 处理顺序

1. 限制请求体大小；
2. 保存原始Body用于本次验签，不写敏感日志；
3. 校验必填Query参数；
4. 校验 `orgId == MOREDIAN_ORG_ID`；
5. 验签；
6. 校验 `callbackTag == REC_SUCCESS`；
7. 校验 `deviceSn == MOREDIAN_DEVICE_SN`；
8. 校验 `recognizeTime` 是合法毫秒时间戳；
9. 按 `dedup_key` 幂等落库；
10. 用 `memberId` 查询 `users.dingtalk_user_id`；
11. 查找同一用户、状态为 `ACTIVE` 且未冻结的预约；有效门禁证据时间窗口为预约开始前 120 分钟的开区间至预约开始后 10 分钟的开区间；
12. 合法事件先幂等落库，即使当时没有匹配预约也保留，后续预约重算仍可使用；
13. 首条有效门禁证据写入预约签到字段；重复事件不重复更新；
14. 提交本地事务；
15. 返回HTTP 200；
16. 卡片更新、迟到通知等非关键外部调用在事务提交后执行。

不得等待钉钉卡片接口完成后才响应魔点，否则会扩大回调超时和重复推送风险。

### 11.8 成功响应

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "result": "0",
  "message": "操作成功"
}
```

### 11.9 失败与重试语义

魔点在HTTP状态码非2xx时重试11次，官方间隔为：

```text
1m, 1m, 3m, 5m, 20m, 30m, 1h, 2h, 4h, 8h, 8h
```

处理原则：

| 情况 | HTTP响应 | 说明 |
|---|---|---|
| 合法新事件并已持久化 | 200 | 正常成功 |
| 合法重复事件 | 200 | 幂等成功 |
| 签名错误 | 401/403 | 拒绝并记录安全日志 |
| 非本机构/非目标设备 | 200或受控拒绝 | 建议安全忽略并告警，避免无意义重试 |
| 临时数据库故障 | 500 | 让魔点重试 |
| 本地无匹配预约 | 200 | 保存未匹配事件供排查，不要求魔点重试 |
| 钉钉卡片更新失败 | 200 | 本地后续重试，不让魔点重放门禁事件 |

### 11.10 Postman Mock要求

测试请求必须使用与实际发送完全一致的原始JSON字符串计算签名。至少覆盖：

1. 正常回调；
2. 同一事件重复发送两次；
3. 错误签名；
4. 错误机构；
5. 错误设备SN；
6. 无匹配预约；
7. 准时识别；
8. 迟到识别；
9. `fileKey`存在与不存在；
10. 数据库首次失败、魔点重试后成功；
11. 原始 JSON 字段顺序或空白不同，并分别基于各自原始 Body 生成正确签名；
12. 同一事件命中多个候选预约，验证固定优先级与排序；
13. 迟到提醒请求结果不确定时复用同一 `outTrackId`，不重复投放。

## 12. 跨接口业务流程

### 12.1 用户免登

```text
H5调用DT-01取得一次性code
  → 后端读取/刷新DT-02 AccessToken
  → 后端调用DT-03取得userid和name
  → 后端查询本地用户与角色
  → 后端签发自己的会话Cookie/Token
```

项目会话凭证由本项目后端签发，不得直接把钉钉AccessToken作为用户登录态。

### 12.2 每日安排卡片

```text
09:00定时任务
  → 查询当天有效预约
  → 生成公共cardData
  → 按钉钉userId生成privateData
  → DT-04创建并投放
  → 保存outTrackId

预约数据变化
  → 数据库事务成功
  → 合并卡片更新任务
  → DT-05更新原卡片
```

### 12.3 门禁识别与迟到提醒

```text
部署时MD-01取得Token
  → MD-02注册REC_SUCCESS

实际刷脸
  → 魔点调用MD-03
  → 验签、设备过滤、去重
  → memberId直接匹配钉钉userId
  → 更新签到/迟到数据
  → DT-05更新今日安排卡片（如模板展示状态）
```

对“未检测到门禁记录”的迟到提醒：

```text
定时任务到达预约开始时间+迟到宽限
  → 检查仍无有效门禁记录
  → 建立appointmentId+LATE_REMINDER唯一任务
  → DT-04新建迟到@提醒卡片
```

回调只证明“收到识别记录”；未收到回调不一定能绝对证明人员未到，因此对外文案使用“尚未检测到门禁记录”。

## 13. 可靠性统一要求

1. 所有第三方调用设置连接超时与响应超时；
2. 仅网络异常、HTTP 5xx、明确可重试错误执行指数退避；
3. 所有重试必须保持业务幂等键不变；
4. 第三方失败不能破坏已提交的预约事务；
5. 预约数据库是事实源，卡片是展示和通知渠道；
6. Token只在后端缓存，日志统一脱敏；
7. 保存第三方平台、接口编号、HTTP状态、业务错误码、requestId、耗时和重试次数；
8. 不记录免登Code、AccessToken、AppSecret、OrgAuthKey和完整签名原文；
9. 所有时间戳入库保存完整时间，并统一按Asia/Shanghai解释业务日期；
10. 本地开发默认使用Mock；只有集成测试环境连接真实钉钉和魔点。
