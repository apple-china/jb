# 开发问题与假设

更新时间：2026-09-07（Asia/Shanghai）

## 当前依据

- 业务冲突以 [V1.0 确认需求基线](加贝云_V1.0_确认需求基线.md) 为准，实施差异以 [V1.0 增量设计与文档差异](加贝云_V1.0_增量设计与文档差异.md) 为准。
- 当前数据均为可重置测试数据，已按新版结构重建；不兼容旧角色、作废状态和旧次数账本。
- 原 V1.1 的魔点、签到和迟到提醒已经进入 V1.0；固定 09:00 安排卡任务已删除。

## 唯一业务待确认

超管、运营、妆造代预约以及管理员修改、取消、冲突例外，哪些场景必须手工填写原因仍未最终确认。当前实现采用“原因可选＋系统始终自动记录操作人、时间、对象、前后值和冲突标记”，没有恢复资源编辑强制手填。

## 外部阻塞

- 缺少真实钉钉 Client ID/Secret、目标群 openConversationId、安排卡/迟到卡模板 ID。前端免登入口与现有后端接口已经接通，并支持公开 Client/Corp ID 构建配置；真实身份适配器、Secret 注入、群卡片及真机流程仍保持禁用或待联调。
- 缺少魔点 OrgID、OrgAuthKey、目标 deviceSn、真实脱敏 `REC_SUCCESS` 原始报文和公网 HTTPS 地址，故目前只完成本地回调链路与签名算法验证。
- 未在目标钉钉 Android、iOS、PC 容器做真机验收。
- 生产备份恢复、日志留存周期、监控平台、告警阈值和接收人属于部署确认项。

## 已采用的最小化设计

- 数据库为事实源，第三方消息为异步投影；外部失败不回滚预约或签到。
- 老师每天单段班次，无跨夜/分段；不做审批、调换、复杂补签、门禁图片下载、历史记录主动轮询、批量操作或导出。
- 安排卡按“群＋预约日期”唯一；迟到提醒按预约唯一；重试复用稳定键。
- 图片限制为 PNG/JPG、2 MB、最大边长 4096；正式素材可在不改变业务结构的情况下替换。
- local/test 使用固定 Mock；production 不注册 Mock 路由，且在真实适配器配置完成前默认拒绝外发。

## 环境事实

- 当前机器无可用 Docker，已使用项目自带 PostgreSQL 16.15 完成真实数据库集成测试；Testcontainers/Compose 未在本机验证。
- 项目目录不是 Git 仓库，无分支和提交历史。
