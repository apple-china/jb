更新日期：2026-09-06（Asia/Shanghai）

## 1. 五种固定角色

同一个人只允许一种角色，不支持自定义角色。

| 角色 | 权限范围 |
|---|---|
| 超管 | 唯一超管，系统最高权限；可分别授权或收回运营账号的修改、取消预约权限 |
| 运营 | 日常维护、代预约；修改和取消须有对应授权；可创建观察员、妆造、主播账号 |
| 观察员 | 查看除密码等敏感信息外的数据，不更新业务数据，不可导出任何数据 |
| 妆造 | 默认查看本人预约，可手动查看其他老师预约；仅为本人代预约，不能修改或取消；仅查看本人排班、工作时间及出勤配置 |
| 主播 | 查看、新建、取消、修改本人预约；可查看今天、明天的公开安排 |

- 运营不可添加超管或运营、修改自己的角色、重置超管密码或停用超管；不得通过凭据或身份绑定间接提权。
- 妆造修改、取消权限关闭，不存在运营向妆造授权的功能。
- 妆造可为任意满足条件的主播代预约，可选任意启用团队，老师只能选择本人。
- “管理员”仅指超管和运营，不包括妆造；妆造的代预约例外单独明确。
- 操作须在服务端验证角色、权限和数据归属，不以页面按钮代替授权。

## 2. 账号与登录

- 初始化唯一超管的钉钉ID和账号密码，不使用通用固定密码，首次登录须更换密码。
- 系统内不能移除超管，不能修改、解绑超管的登录方式，仅可修改密码。无法登录时提示“系统出错了，请联系IT部门”。
- 创建账号时至少提供一种登录方式：钉钉绑定或账号密码，也可同时提供。
- 钉钉与密码登录对应同一账号、同一权限；钉钉ID不能重复绑定，账号名不能重复。
- 钉钉内优先免登，失败可重试，无权限或免登失败时提供密码备用入口；钉钉外密码登录。
- 停用账号使已有登录失效。
- 超管可管理其他账号启停、解绑钉钉及重置密码；运营可管理观察员、妆造、主播的相应事项。
- 运营修改本人密码须验证原密码；忘记密码由超管重置。
- 无钉钉绑定的主播允许创建账号；当前账号列表不再显示“未绑定钉钉，无法自动签到和接收 @ 提醒”的旧提示，后续强制绑定方案另行确认。其预约仍不能伪造签到证据或 @ 对象。

## 3. 系统、出勤与资源开关

- 系统关闭时，超管、运营仍可进入和操作；其他角色进入提示“预约暂未开放”。
- 关闭期间继续接收门禁、计算签到、保留已有安排并处理通知任务。
- 账号启用决定能否访问；主播出勤决定能否为其新建预约。
- 主播出勤由超管、运营维护，新账号默认开启，持续有效直到人工修改，不每日自动重置。
- 所有角色为主播预约时，都须满足主播出勤、老师启用和出勤、团队启用等资源条件。
- 资源开关、排班变化不自动取消或改派已有预约；后续修改时重新校验。

## 4. 老师排班与服务时间

- 超管、运营维护工作日和上下班时间；按星期多选，默认周一至周日，08:00—20:00。
- 每天单段班次，不增加分段或跨夜班次。
- 老师启用、出勤开关开启、预约日期属于工作日、完整服务区间处于班次内，须同时成立。
- 每条预约占用20分钟，开始时间仅限每小时00、10、20、30、40、50分；班次设置应与刻度一致。
- 不增加额外交接、清洁缓冲。12:00—12:20之后可接12:20—12:40；20:00下班最晚19:40开始。
- 团队不限制同时人数，无主播与团队、老师与团队固定绑定。

## 5. 预约状态与资格

- 所有角色新建仅支持今天、明天，日期及时间统一按北京时间判断。
- 每个主播每个预约日期同时最多1条有效记录；今天、明天可各有1条。
- 不限制累计创建次数，不设置创建次数配置，也不限制实际接受妆造次数。
- 新建成功为“有效”；预约仅有“有效、已取消”，彻底移除新业务的作废功能。
- 取消同时释放老师时段和主播该日期资格，可以重新预约，但须满足新建条件。
- 已取消不能恢复，只能新建；不可更新已取消预约业务内容或签到状态。
- 修改不能更换预约日期或预约主播。

## 6. 主播操作与次数

- 新建须至少提前20分钟，恰好20分钟允许；资源合法且与该老师其他有效预约不重叠。
- 本人取消须原预约有效、至少提前20分钟，每个预约日期最多成功取消2次；取消时冻结签到。
- 本人修改须原预约有效；原、新开始时间均至少提前20分钟，每个预约日期最多成功修改3次。
- 可改老师、开始时间、团队。任何字段修改均重新校验资源、班次、刻度、冲突；原老师不可用时须换为可用老师，否则不能提交。
- 修改失败保留原预约和原时段；成功后才变更占用。改时间重算签到，仅换老师或团队不重算。
- 次数按“主播＋预约日期”跨预约记录累计，取消重约不清零，午夜不重置同一预约日期的次数。
- 取消和修改分别计数。一次成功修改一个或多个字段计1次；失败、重复提交、内容不变不计。
- 达到取消上限后仍可在资格释放后新建，但不能再自行取消；达到修改上限后重建也不能再自行修改。
- 管理员取消、修改不消耗、不返还主播次数；超次数后纯人工联系管理员，不增加申请审批流程。
- 多页面同时操作不能突破资格或次数。主播自行修改代预约记录时仍适用主播规则，不继承冲突例外。

## 7. 管理员与妆造代预约

- 超管、运营新建至少提前1分钟，恰好1分钟允许；仍只支持今天、明天。
- 检查主播日期资格、主播出勤、老师启用/出勤/工作日/完整工作时间及团队启用。
- 可跳过老师时间冲突限制，但页面须明确提示冲突；不限制操作次数。
- 妆造代预约默认适用提前1分钟及允许冲突，资源检查相同，但老师只能是本人。

## 8. 管理员修改、取消

- 超管和具备对应授权的运营，只能修改、取消今天或明天的有效预约，不操作过去日期。
- 修改时间：原、新开始时间均须至少提前1分钟。
- 仅换老师或团队：不受提前量限制，开始前不足1分钟及已开始后也可操作；不改变日期、时间，不重算签到。
- 修改均校验目标资源和班次条件，仅豁免老师冲突，并提示冲突。
- 取消无提前量限制，可取消已开始预约；冻结签到并释放资格。
- 管理员取消、修改无次数上限，不影响主播计数。
- 具体人工原因填写范围尚待确认，见第15节；不可将建议冒充已确认规则。

## 8.1 预约记录查询与导出

- 超管、运营、观察员使用历史日期区间筛选；开始默认当月 1 日，截止默认当天，并提供含当天在内的近 7 日、近 30 日快捷项。
- 筛选维度为开始、截止、主播、化妆师、签到状态、预约状态；签到状态和预约状态默认全部。
- 结果显示当前筛选总条数；总数超过 30 条才显示分页，支持每页 30、50、100 条。
- 超管、运营可导出当前筛选条件下的全部记录为 XLSX，观察员和化妆师不可导出。导出不受当前页限制。
- 导出包含序号、预约日期、预约时间、化妆师、团队、主播名字、预约状态、签到状态、迟到分钟、完整修改记录、提交时间、打卡时间、代预约人、主播 ID、数据 ID。
- 化妆师继续仅查看今天、明天且限定本人记录；主播端公开安排范围不变。发送卡片与历史筛选解耦，点击后单独选择今天或明天。

## 9. 魔点门禁

- V1.0 接入真实魔点回调，保存打卡证据，校验来源、身份、事件内容，去重并处理延迟、乱序。
- 使用实际打卡时间，不用回调接收时间判断迟到。
- 按门禁身份与绑定的钉钉身份关联主播；无绑定则无法自动签到或 @，须提示。
- 无匹配预约的门禁记录也保存，供新建、改时间后查询。
- 无出门类型，已到公司又离开仍算已到司；到公司等同到妆造现场。
- 不增加复杂补签、门禁图片下载或主动轮询魔点历史。

## 10. 签到判定与冻结

预约状态、签到状态独立显示。设开始时间为T，有效打卡范围是T－120分钟之后，至预约日期当天结束之前，取首次有效打卡；前120分钟整及更早无效，不跨天。

| 有效打卡 | 时间条件 | 状态 |
|---|---|---|
| 无 | 当前时间＜T | 待到司 |
| 无 | T≤当前时间＜T＋10分钟 | 未到 |
| 无 | 当前时间≥T＋10分钟 | 迟到 |
| 有 | 首次有效打卡时间＜T＋10分钟 | 已到司 |
| 有 | 首次有效打卡时间≥T＋10分钟 | 迟到 |

- 08:00打卡、12:00预约、中间无打卡，按无有效证据处理；达到宽限后判迟到。
- “迟到”包括晚到和尚无有效打卡，页面配合显示实际打卡时间或无有效打卡提示。
- 门禁回调、定时检查、新建和改预约时间使用同一套判定。
- 有效预约可依据延迟的准时证据纠正签到并留痕。
- 取消时按当时已知证据冻结签到；取消后绝不更新，后到证据仅继续保存。
- 新有效预约重新按时间窗口查询证据；符合窗口的原打卡可再次使用，旧取消记录仍保持冻结。不沿用旧设计“一条门禁事件只能用于一条预约”的限制来阻止该行为。

## 11. 钉钉卡片与迟到通知

- 取消固定每日09:00发送预约安排卡片的规则，改为首次有效预约自动发送及管理员手动触发。
- 超管、运营可手动触发预约安排卡片发送；妆造、观察员、主播无手动发送权限。这里“管理员”沿用角色定义指超管、运营。
- 某预约日期第一条有效预约提交成功后，检查该预约日期的群卡片是否已发送；未发送则自动发送。按预约日期而非提交日期区分卡片：今天首次提交明天的预约，可立即发送明天的安排卡片，无须等到明天。
- 同一群、同一预约日期沿用一张当前安排卡片；已发送时更新原卡，不因手动触发、取消后再次出现首条有效预约或同时提交而重复发布。原卡失效且无法恢复时，沿用替代卡处理规则。
- 卡片展示对应预约日期的有效预约，按开始时间排序，保留进入预约系统入口；之后新建、修改、取消更新原卡。没有有效预约且未手动触发时，不再定时自动发空卡。
- 初次发送失败继续重试，不能将发送失败当作已成功发送，也不能因重试重复发卡；不影响已提交预约。此变更只调整预约安排卡片触发方式，不改变迟到提醒条件。
- 钉钉私有预约内容只针对可识别的绑定身份；不在卡片内直接修改业务。
- V1.0 新增独立迟到群卡片及真实 @ 主播。
- 只提醒达到开始后10分钟、仍无有效打卡的主播；已经迟到打卡的人仅显示迟到，不再催到场。
- 每条预约最多提醒一次；取消后新预约作为新安排独立计算提醒资格，不按主播＋日期合并。
- 重复回调、重复任务、失败重试不得重复通知；发送失败可重试，不回滚预约或签到。
- 延迟证据纠正签到后不重复 @；已取消记录不能作为新的催到场对象。
- 无钉钉绑定时无法 @，须显式提示，不能生成虚假的通知成功记录。

## 12. 日志与可靠性

- 记录登录成功、失败、权限拒绝、账号和权限变更、密码重置、解绑、预约变更、出勤排班及开关变更、签到变化和纠正、卡片发送及异常。
- 日志包含操作人或系统来源、时间、对象、变更前后内容；取消重约可追溯关联。
- 密码、免登码、接口凭据不进入日志；业务角色不能覆盖或删除日志。
- 失败不扣次数、不释放原时段、不留下半完成预约；并发时资格、次数及状态一致。
- 管理员/妆造冲突例外不使主播绕过冲突限制。
- 外部接口失败不撤销成功预约；正式发布须验证真实钉钉登录、门禁身份和回调、签到边界及群内 @。
