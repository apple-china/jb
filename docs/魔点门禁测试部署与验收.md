# 魔点门禁测试部署与验收

本环境采用人工注册机构回调，只订阅 `REC_SUCCESS`。回调地址固定为：

```text
https://jb.huixinghub.top/api/v1/integrations/moredian/recognition-events
```

## 1. 配置与部署

在服务器已有且不纳入 Git 的 `.env.dingtalk-test` 中填写：

```dotenv
MOREDIAN_ORG_ID=<机构 ID>
MOREDIAN_ORG_AUTH_KEY=<机构授权密钥>
MOREDIAN_DEVICE_SN=<唯一允许的门禁设备 SN>
MOREDIAN_REQUIRE_SIGNATURE=true
MOREDIAN_CALLBACK_URL=https://jb.huixinghub.top/api/v1/integrations/moredian/recognition-events
```

不要把 APPKey、OrgAuthKey、AccessToken 或真实回调签名写入仓库、命令输出截图和日志。然后执行：

```bash
cd /opt/stacks/jiabei
git fetch origin
git switch codex/moredian-access-attendance
git pull --ff-only origin codex/moredian-access-attendance

docker compose --env-file .env.dingtalk-test \
  -f docker-compose.yml -f docker-compose.dingtalk-test.yml config --quiet
docker compose --env-file .env.dingtalk-test \
  -f docker-compose.yml -f docker-compose.dingtalk-test.yml \
  up -d --build --force-recreate backend frontend
docker compose --env-file .env.dingtalk-test \
  -f docker-compose.yml -f docker-compose.dingtalk-test.yml ps
```

## 2. 人工注册回调

当前使用“钉钉渠道云端接口应用”，不要调用旧企业内部应用的
`/org/getOrgAccessToken`。进入魔点开放平台的应用详情，选择已授权机构后点击
“调试”，使用右上角“一键获取 Access Token”，再打开“回调接口 → 注册回调”。填写：

```text
callbackUrl = https://jb.huixinghub.top/api/v1/integrations/moredian/recognition-events
callbackTag = REC_SUCCESS
```

也可以把在线调试取得的临时 AccessToken 交给仓库脚本；脚本不会保存或打印 Token：

```bash
export MOREDIAN_CALLBACK_URL='https://jb.huixinghub.top/api/v1/integrations/moredian/recognition-events'
./scripts/register-moredian-callback.sh
unset MOREDIAN_ACCESS_TOKEN
```

脚本会静默提示输入 AccessToken。返回应为 HTTP 2xx 且 `result` 为 `"0"`。
`addOrgCallback` 是覆盖式注册；以后增加事件类型时必须一次提交完整标签集合。
程序或服务器重启不会清除魔点云端的注册信息。

## 3. 真实 `REC_SUCCESS` 验收

1. 先创建当天有效预约，主播账号的 `dingtalk_user_id` 必须与魔点回调 `memberId` 完全一致。
2. 预约开始前 120 分钟之后、开始后 10 分钟之前，在配置的唯一设备上完成一次真实识别。
3. 实时查看脱敏日志：

```bash
docker compose --env-file .env.dingtalk-test \
  -f docker-compose.yml -f docker-compose.dingtalk-test.yml \
  logs -f --since=10m backend | grep --line-buffered 'Moredian callback'
```

正常日志结果应为 `ACCEPTED`；平台重推同一事件时应为 `DUPLICATE`。日志中的人员和设备标识已脱敏，不包含原始 Body、密钥或完整签名。

异常回调当前只生成 `Moredian callback alert` 结构化告警日志，不发送钉钉通知；后续版本再接入通知渠道。门禁原始事件默认每 7 天检查一次，删除超过 180 天或超出最新 60000 条的数据。预约中已保存的签到时间和 `ARRIVED` 结果不因原始事件清理而回退。

4. 核对事件、预约状态和卡片刷新任务：

```bash
docker compose --env-file .env.dingtalk-test \
  -f docker-compose.yml -f docker-compose.dingtalk-test.yml exec -T db \
  psql -U jiabei -d jiabei_dingtalk_test -c \
  "SELECT external_event_id, event_type, occurred_at, received_at FROM gate_event ORDER BY received_at DESC LIMIT 5;"

docker compose --env-file .env.dingtalk-test \
  -f docker-compose.yml -f docker-compose.dingtalk-test.yml exec -T db \
  psql -U jiabei -d jiabei_dingtalk_test -c \
  "SELECT start_at, streamer_name_snapshot, attendance_status, attendance_evidence_at FROM appointment ORDER BY updated_at DESC LIMIT 5;"

docker compose --env-file .env.dingtalk-test \
  -f docker-compose.yml -f docker-compose.dingtalk-test.yml exec -T db \
  psql -U jiabei -d jiabei_dingtalk_test -c \
  "SELECT job_type, status, attempt_count, last_error_code, updated_at FROM integration_job WHERE job_type='CARD_REFRESH' ORDER BY updated_at DESC LIMIT 5;"
```

预期结果：只新增一条 `gate_event`，预约更新为 `ARRIVED` 并记录门禁证据时间，随后产生或合并一条 `CARD_REFRESH`，群内原安排卡更新签到状态。非目标机构、非目标设备和非 `REC_SUCCESS` 事件会安全返回成功但不落库；无匹配预约的合法事件仍落库，后续预约重算时可使用。
