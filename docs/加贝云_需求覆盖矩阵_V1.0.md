### 1.1 状态口径

| 状态 | 含义 |
|---|---|
| 设计完成，待开发 | 原始编制状态；若与第 0 节冲突，以第 0 节的实际回填为准。 |
| 契约完成，待联调 | 已形成接口契约和 Mock 方案，仍需测试账号或真实环境验证。 |

| 明确排除 | 已确认不进入产品 V1.0/V1.1，不得作为隐性开发任务。 |

### 1.2 代码位置口径

本项目已在 `src/frontend`、`src/backend`、`scripts` 中形成实现，但当前目录没有 `.git` 元数据。原始明细表中的建议路径作为设计映射保留；真实路径以第 0 节、README 和开发进度为准。

### 1.3 测试编号口径

- `AC-*`：验收清单。
- `FT-*`：功能测试。
- `IT-*`：接口、并发与可靠性测试。
- `SEC-*`：安全测试。
- `CP-*`：兼容、部署与上线检查。
- “待补”表示现有工作簿没有足够具体的独立用例，应在开发对应模块前补入。

### 11.3 建议补入测试工作簿的用例

1. 今天无可用时段时默认明天；仍有可用时段时默认今天。
2. 浏览器刷新复用本系统会话，不重复调用钉钉 DT-02/DT-03。
3. 管理员修改预约日期被拒绝；缺少操作原因被拒绝。
4. 两名管理员同时修改同一预约时，旧版本请求失败且不覆盖新值。
5. 创建和取消事务在审计、偏好、账本或发件箱写入失败时完整回滚。
6. 每日空卡片、`CANCELLED/VOIDED` 过滤、私有区角色组合和原卡不可恢复降级。
7. 登录限流、安全响应头、上传格式/大小/解码边界。
8. 魔点回调乱序：迟到事件先到、准时事件后到时的确定性结果和提醒不重复。

## 12. 维护规则

1. 产品规则变化先更新项目说明书，再同步技术设计、接口契约、测试工作簿和本矩阵。
2. 每次合并功能代码前，至少回填对应需求的真实代码路径、状态、测试结果和缺陷编号。
3. 一个需求若无测试用例，不得标为“已实现”；外部接口未真联调不得标为“已验收”。
4. 新需求使用现有模块前缀递增编号，不重排旧编号，避免提交记录失去追踪关系。
5. 被明确排除的能力如重新纳入，必须先建立新版本范围、状态机、接口和验收用例，不直接修改为“开发中”。
